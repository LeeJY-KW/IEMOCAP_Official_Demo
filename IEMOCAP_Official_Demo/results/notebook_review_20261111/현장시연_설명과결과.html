IEMOCAP 이산·연속 감정 인식 평가¶

학습 완료 모델을 이용한 5-fold 현장 시연¶

목적: 이산 감정 클래스 및 Valence/Arousal 예측을 IEMOCAP의 원본 사람 주석(Ground Truth)과 비교한다. 각 fold에서 학습·개발에 사용하지 않은 세션만 해당 fold의 가중치로 추론한다.

기존 갈망 과제 노트북처럼 단계 설명 → 함수와 입력·출력 → 코드 실행 → 결과 확인 순서로 구성했다. 코드 셀을 위에서부터 Shift+Enter로 실행한다. 표·그래프는 해당 셀 아래에서 확인한다.

순서 현장에서 확인할 내용
1. 실행 준비 라이브러리, 경로, 파일 무결성
2. 평가 데이터와 정답 특징 차원, 감정 라벨, V/A 원본 주석, 채점 대상
3. 5-fold 평가 조건 학습·개발·시험 세션과 가중치 선택 기록
4. 한 대화 추론 모델 로딩 → 저장 통계로 정규화 → 실제 forward → 정답 비교
5. 전체 5-fold 평가 10개 가중치 추론, fold별 점수, 평균±표본SD
6. 결과 시각화 fold별 성능, 한 대화의 V/A 정답·예측
7. 독립 검증과 결과 보존 별도 채점, 출력 파일 확인

준비된 모델: Base InductiveGraph(multi_graph, observed gate). 7분류와 V/A 회귀는 각각 학습한 별도 모델이다. 현장에서는 가중치 로딩·추론·채점만 수행한다. 자체 수집 어노테이션이 아직 없어 IEMOCAP 원본 주석으로 준비한 예비 평가다. 입력은 사전 추출한 음성·텍스트·영상 특징이며 원음·영상에서 특징을 추출하는 단계는 사전에 완료했다.

실행 환경: Python 3.10, 패키지 폴더 전체, requirements-notebook.txt의 패키지가 필요하다. 방문 전에 python -m pip install -r requirements-notebook.txt로 준비하고 그 Python 환경을 노트북 커널로 선택한다. CPU 4스레드가 기본이다. 실행 중 오류가 발생하면 다음 셀로 넘어가지 말고 오류를 해결한 뒤 해당 단계부터 다시 실행한다.

def show_table(rows, columns=None, limit=None):
    rows = list(rows)
    if not rows:
        print("표시할 행이 없습니다.")
        return
    columns = list(rows[0]) if columns is None else columns
    shown = rows if limit is None else rows[:limit]
    header = "".join("<th>" + html.escape(str(c)) + "</th>" for c in columns)
    body = "".join("<tr>" + "".join("<td>" + html.escape(str(r[c])) + "</td>" for c in columns) + "</tr>" for r in shown)
    display(HTML('<div style="overflow-x:auto"><table border="1" cellpadding="6"><thead><tr>' + header + '</tr></thead><tbody>' + body + '</tbody></table></div>'))
    if limit is not None:
        print(f"전체 {len(rows):,}행 중 앞 {len(shown):,}행 표시")

2-2. 원본 정답 주석 읽기¶

Ground Truth는 모델 예측이 아니라 IEMOCAP에 포함된 사람 주석이다. 원본 주석 헤더의 [시작 - 종료] 발화ID 감정 [Valence, Activation, Dominance] 중 감정과 앞 두 수치를 사용한다. Activation은 이 평가에서 Arousal로 표기한다. Dominance는 이번 채점 대상이 아니다.

실행 내용: Fold 1의 첫 번째 시험 대화를 예시로 고정하고 원본 헤더와 평가 정의를 나란히 출력한다. 예시는 예측 정답 여부를 보기 전에 정하므로 성공 사례를 선별하지 않는다.

확인: 발화 ID와 원본 감정·V/A가 평가 정의에 일치해야 한다. 캐시의 과거 6분류 labels 필드는 사용하지 않는다.

3. 5-fold 평가 조건 확인¶

3-1. 학습·개발·시험 세션 구분¶

Fold k는 Session k를 시험, 다음 순환 세션을 개발, 나머지 3개 세션을 학습에 사용했다. 개발 세션은 가중치 선택에 사용했으므로 현장 시험 데이터에 포함하지 않는다.

실행 내용: 기존 동결 프로토콜에서 분리표를 읽고 세 집합이 겹치지 않는지 확인한다.

한 발화가 다른 fold의 학습에는 등장할 수 있지만 그 발화를 예측하는 Fold k 모델의 학습·개발에는 등장하지 않는다. 5개 모델을 앙상블하지 않는다. 전체 OOF(out-of-fold) 결과에서 각 발화는 과제별로 한 번만 채점 대상이 된다.

def load_frozen_model(task, fold_number):

def prepare_inputs(features, structure, normalizer):
    batch = {name: torch.as_tensor((features[name] - normalizer[name]["mean"]) / normalizer[name]["std"],

@torch.inference_mode()
def predict_dialogue(model, batch, task):
    raw = model(batch)
    prediction = raw.softmax(-1) if task == "classification" else 3 + 2 * torch.tanh(raw)
    result = prediction.cpu().numpy()
    assert np.isfinite(result).all()
    return result

5-3. 지표 계산 원리와 독립 재계산¶

분류의 Weighted F1은 클래스별 F1에 정답 표본 비율을 곱해 더한다.

[ F1_{weighted}=\sum_{c=1}^{7}\frac{n_c}{N}\frac{2TP_c}{2TP_c+FP_c+FN_c} ]

연속 감정은 Valence와 Arousal 각각 다음 CCC를 구한 후 평균한다. 분산·공분산은 모집단 정의(ddof=0)를 사용한다.

[ CCC(y,p)=\frac{2\operatorname{cov}(y,p)}{\operatorname{var}(y)+\operatorname{var}(p)+(\bar y-\bar p)^2} ]

Function calculate_ccc¶

  • Args: truth, prediction — 유효 표본의 한 차원 정답·예측 배열.
  • Returns: float64로 재계산한 CCC. 분모가 0인 퇴화 입력은 오류로 중단한다.

실행 내용: 방금 저장한 fold별 예측을 읽어 sklearn 분류 지표 및 위 CCC 식으로 재계산한다. 원래 계산된 지표와 오차 1e-10 이내인지 확인한다. 이 오차는 동일한 저장 예측의 채점 구현 비교용이다.

def calculate_ccc(truth, prediction):
    truth, prediction = np.asarray(truth, dtype=np.float64), np.asarray(prediction, dtype=np.float64)
    covariance = np.cov(truth, prediction, ddof=0)
    denominator = covariance[0, 0] + covariance[1, 1] + (truth.mean() - prediction.mean()) ** 2
    if denominator <= 0:
        raise ValueError("CCC 분모가 0인 입력입니다.")
    return float(2 * covariance[0, 1] / denominator)

7-2. 전체 저장 예측의 독립 감사¶

Function audit_demo.audit¶

  • 기능: 실제 저장 예측을 독립적으로 채점하고 원래 동결 예측과 대조한다. ID·정답·채점 마스크·전체 OOF 중복 여부도 검사한다.
  • Args: output — 이번 실행 결과 폴더 OUT.
  • Returns: audit_result — 통과 여부와 fold별 수치 차이. independent_audit.json도 저장한다.

같은 저장 예측에서 다시 계산한 지표의 허용 오차는 1e-10이다. 이전에 GPU로 계산한 예측과 현재 CPU 예측의 비교에는 float32 연산 차이를 고려해 최대 절대 차이 1e-4를 적용하며, 분류 클래스 결정은 정확히 일치해야 한다. 허용 오차는 실행 후 점수에 맞춰 바꾸지 않는다.

확인: 10개 fold와 10,039개 비교 행이 PASS로 출력되어야 한다.

8. 현장 설명 문구와 해석 범위¶

학습이 완료된 이산 감정 분류 모델과 연속 감정 회귀 모델의 fold별 가중치를 불러옵니다. IEMOCAP의 5개 세션으로 구성한 5-fold 평가에서 각 fold의 학습·개발에 사용하지 않은 시험 세션의 멀티모달 특징을 입력합니다. 예측 감정 클래스와 원본 감정 라벨을 비교해 Weighted F1을 산출하고, 예측 Valence/Arousal과 원본 발화별 주석을 비교해 각 차원의 CCC 및 평균 CCC를 산출합니다. 현장에서는 재학습이나 모델 선택 없이 추론과 채점만 수행합니다.

이 결과는 IEMOCAP 통제 환경의 발화 단위 예비 검증이다. 자체 수집 자료의 어노테이션 성능, 실환경(in-the-wild), 프레임 단위 연속 감정 검증, 완전히 새로운 blind test 또는 기관 인증 완료로 표현하지 않는다. 대화 내부 양방향 문맥을 사용하며 실시간 인과 추론을 검증한 결과도 아니다.

분류와 회귀는 별도 학습 모델이며 정답 표본 수가 다르다. 이산·연속 결과를 같은 표에서 보여주는 것은 발화 ID를 이용한 연결이며, 공동 멀티태스크 학습이나 모델 예측을 정답으로 삼은 자체 어노테이션 검증을 의미하지 않는다.
